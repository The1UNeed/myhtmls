myhtmls

Build summary, 2026-08-15. Authenticated static HTML draft publishing for agents at myhtmls.dev. A fork of postplan 0.0.4 (MIT, t3dotgg) ported from Railway to Vercel. Source: github.com/The1UNeed/myhtmls · Package: npm: myhtmls@0.1.0

Why

The previous workflow published every HTML artifact as a separate Vercel preview deployment with SSO protection enabled. Three failures: agents could not curl their own artifacts back (the login page came back instead), every document produced a new deployment with a new URL so revisions broke links, and the promised <draft-id>.myhtmls.dev URLs did not exist. myhtmls replaces this with one long-lived service: stable per-draft URLs, version history, and byte-for-byte serving to every client.

Deliberate deviations from upstream

  • Uploads require an API key. Upstream accepts anonymous uploads. On a personal budget with a per-instance rate limiter, that is an open quota drain. MYHTMLS_ALLOW_ANONYMOUS_UPLOADS=1 restores upstream behavior.
  • Inline scripts run, sandboxed, with a per-version CSP. Upstream serves script-src 'none'. myhtmls serves a CSP sandbox without allow-same-origin: scripts execute with an opaque origin, so storage throws and fetch, forms, frames, and cookies are dead. Versions containing inline script additionally lose network images and fonts (img-src data:) and popups, because an independent review found that img-src https: plus scripts allowed silent exfiltration of viewer input via image beacons. Scripts and arbitrary-host images are never available together.
  • No search indexing. Drafts send X-Robots-Tag: noindex, nofollow; the apex serves a disallow-all robots.txt. Reads are gated only by the unguessable 12-char draft id.
  • Thin CLI install. Server packages live in devDependencies, so npx myhtmls installs about 2 MB (commander + parse5) instead of about 40 MB. Vercel installs devDependencies at build time.

Independent review

A gpt-5.6-sol (Codex) review of the fork delta against pristine upstream produced three findings: the image-beacon exfiltration channel (confirmed, fixed with the per-version CSP above), a Node 20 incompatibility in the Neon driver (confirmed, engines raised to 22), and server deps in devDependencies (valid concern, kept as a documented trade-off). It found no auth bypass, no SSRF path through the stored blob URLs, and no way to write an arbitrary object_key.

Verification, all against production

  • Byte-for-byte serving: diff of curl output vs the source file is empty on all four URL forms (subdomain, subdomain /raw, apex /d/<id>/raw, pinned /v/1/raw)
  • Versioning: re-upload of the same file updated the same draft to v2; v1 bytes unchanged; git repo auto-linked in myhtmls list
  • Auth: uploads without a key get 401; server-side HTML policy rejects what the CLI rejects when the CLI is bypassed
  • Sandbox, tested in a real browser: inline script executed; localStorage, cookies, and fetch all threw
  • Per-version CSP live: scripted draft gets img-src data:, script-free draft keeps img-src https:
  • Delete: draft removed via API, subsequent fetch 404
  • Registry package: npm exec myhtmls@0.1.0 runs the CLI with the bin entry intact

Usage

npx myhtmls upload ./plan.html          # returns https://<draft-id>.myhtmls.dev
npx myhtmls upload ./plan.html --new    # force a fresh draft
npx myhtmls list                        # drafts with repo, versions, timestamps
npx myhtmls auth login                  # mint a key in the browser, paste back
curl https://<draft-id>.myhtmls.dev/raw # exact uploaded bytes, any client
